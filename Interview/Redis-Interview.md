## Redis类型和使用场景

面试题: Redis类型以及各自的使用场景?

Redis 主要有 5 种基本数据类型，随着版本更新，还引入了位图（Bitmaps）、超日志（HyperLogLog）、地理位置（GEO）以及流（Stream）等高级类型。在实际开发中，可根据数据的结构化程度、访问频率和原子性要求来选择。

1. **String (字符串)**: String 是最基础的类型，可以存储文本、数字甚至是序列化后的对象

+ 使用场景：
  + **缓存：** 最常用的场景，存储 Session、Token 或简单的 JSON 对象。
  + **计数器：** 利用 `INCR` 和 `DECR` 命令实现原子自增，比如点赞数、播放量。
  + **分布式锁：** 利用 `SETNX` 指令（SET if Not eXists）来实现。

2. **Hash (哈希)**:  适合存储对象，特别是对象的字段经常需要单独更新时。相比 String 序列化整个对象，Hash 更加节省空间且灵活

+ 使用场景：
  + **用户信息/购物车：** 比如 Key 是用户 ID，Field 是商品 ID，Value 是商品数量。

3. **List (列表)**: List 是简单的字符串列表，按照插入顺序排序，底层实现是双向链表, 支持两端弹入弹出

+ 使用场景:
  + **消息队列：** 利用 `LPUSH` 和 `RPOP` 实现简单的生产消费者模型。
  + **最新动态：** 比如朋友圈动态、新闻列表，只保留最近的 N 条数据。

4. **Set (集合)**: Set 是无序且唯一的集合。它的核心优势在于支持**交集、并集、差集**运算

+ 使用场景：
  + **去重计数：** 比如记录 IP 访问量（UV）
  + **社交关系：** 利用交集实现“共同好友”，差集实现“可能认识的人”。

5. **ZSet (Sorted Set - 有序集合)**: ZSet 在 Set 的基础上增加了一个 Score 分数，数据按分数排序。

+ **使用场景：**

  - **排行榜：** 比如直播间实时贡献榜、热搜榜。

  - **带权重的任务队列：** 根据优先级处理任务。

6. **Bitmap (位图)：** 适合“只有两种状态”的极大数据量场景，如：**用户签到**、**日活统计**，非常节省内存。
7. **HyperLogLog：** 适合**基数统计**，比如统计网页的 UV(独立访客数）

8. **Geo 地理位置**: 

+ 场景:
  + **附近的人/店铺：** 比如微信附近的人、美团外卖搜索附近 3 公里的商家。
  + **距离显示：** 实时计算用户当前位置与目的地的距离。
